# Media System URL Usage Guide

## Overview

The DecentEdu application uses a dual-storage strategy for media assets:

- **Public assets** (CMS content): Stored on `public` disk, served via `/storage/` URLs
- **Private assets** (photos, logos): Stored on `local` disk, served via authenticated API route

## Asset Categories

### CMS Category (`cms`)
- **Storage Disk**: `public` (storage/app/public/)
- **URL Pattern**: `/storage/{media-id}/{filename}`
- **Conversions**: thumb (300x300), preview (1200x1200) - WebP format
- **Serve Route**: NO (404s if accessed via `/api/v1/cms/media/{id}/file`)
- **Frontend Usage**: Use URLs directly from API response (`asset.url`, `asset.thumb_url`, `asset.preview_url`)

### Photo Category (`photo`)
- **Storage Disk**: `local` (storage/app/private/)
- **URL Pattern**: `/api/v1/cms/media/{id}/file`
- **Conversions**: thumb, preview (with `?conversion=` query parameter)
- **Serve Route**: YES (requires authentication)
- **Frontend Usage**: Use `assetFileUrl(id, 'thumb')` helper function

### Logo Category (`logo`)
- **Storage Disk**: `local` (storage/app/private/)
- **URL Pattern**: `/api/v1/cms/media/{id}/file`
- **Conversions**: thumb, preview (with `?conversion=` query parameter)
- **Serve Route**: YES (requires authentication)
- **Frontend Usage**: Use `assetFileUrl(id, 'thumb')` helper function

## API Response Structure

All assets return the following structure via `toApiPayload()`:

```typescript
interface AssetPayload {
    id: number;
    name: string;
    alt: string | null;
    caption: string | null;
    mime_type: string | null;
    size: number | null;
    url: string | null;              // Full URL (category-dependent)
    thumb_url: string | null;        // Thumbnail URL (images only; falls back to url)
    preview_url: string | null;      // Preview URL (images only; falls back to url)
    srcset: string | null;          // Responsive image srcset (public images only)
}
```

`thumb_url` / `preview_url` are only conversion URLs when that conversion actually exists on
disk. Formats the image driver cannot rasterise (SVG, ICO) get the original file's URL instead,
so a client can always render `thumb_url` for an image without checking for a 404. Non-images
(PDF, video, audio) stay `null` on both.

## Frontend Usage Examples

### CMS Assets (Public)
```tsx
// Correct: Use URLs from API response
<img 
    src={asset.thumb_url ?? asset.url ?? ''} 
    alt={asset.alt ?? asset.name} 
/>

// Incorrect: Do NOT use assetFileUrl for CMS assets
<img src={assetFileUrl(asset.id)} /> // This will 404
```

### Photo/Logo Assets (Private)
```tsx
// Correct: Use assetFileUrl helper
<img 
    src={assetFileUrl(employee.photo_id, 'thumb')} 
    alt={employee.name} 
/>

// Alternative: Use if available in response
<img 
    src={employee.photo_url} 
    alt={employee.name} 
/>
```

## Backend Usage

### Querying Assets
```php
// Always eager-load media relationship
$asset = Asset::with('media')->find($id);

// For CMS blocks
$galleryAssets = Asset::query()
    ->with('media')
    ->whereIn('id', $imageIds)
    ->get()
    ->map(fn (Asset $a) => $a->toApiPayload())
    ->values()
    ->all();
```

### Serving Assets
```php
// Public assets (CMS)
// URLs are automatically generated by Spatie MediaLibrary
// No controller action needed

// Private assets (photo/logo)
Route::get('media/{id}/file', [AssetController::class, 'serve'])
    ->whereNumber('id');
```

## Troubleshooting

### Images Not Displaying

1. **Check Storage Link**:
   ```bash
   ls -la public/storage
   # Should be a symlink to ../storage/app/public
   ```

2. **Verify File Permissions**:
   ```bash
   ls -la storage/app/public/
   # Files should be readable
   ```

3. **Check APP_URL**:
   ```bash
   grep APP_URL .env
   # Should match your actual domain
   ```

4. **Test URL Generation**:
   ```php
   $asset = Asset::with('media')->first();
   dump($asset->toApiPayload());
   ```

## URL Generation Flow

### Public Assets (CMS)
1. Upload → Stored in `storage/app/public/`
2. Conversions generated in `storage/app/public/{id}/conversions/`
3. Spatie MediaLibrary generates URLs: `/storage/{id}/{filename}`
4. Frontend uses URL directly from API response

### Private Assets (Photo/Logo)
1. Upload → Stored in `storage/app/private/`
2. Conversions generated in `storage/app/private/{id}/conversions/`
3. API returns route URL: `/api/v1/cms/media/{id}/file?conversion=thumb`
4. Frontend requests route → `AssetController@serve()` streams file
5. Authentication required

## Best Practices

1. **Always eager-load media relationship** when querying assets
2. **Use correct URL pattern** for each asset category
3. **Never hardcode asset paths** - always use generated URLs
4. **Check asset category** before determining URL strategy
5. **Test image display** with both public and private assets

## Common Mistakes

❌ **Using assetFileUrl() for CMS assets** - will 404
❌ **Using direct URLs for photo/logo assets** - won't work (no public access)
❌ **Not eager-loading media relationship** - causes N+1 queries or null URLs
❌ **Forgetting storage link** - /storage URLs will 404

✅ **Use asset.url/thumb_url/preview_url from API** for CMS assets
✅ **Use assetFileUrl() helper** for photo/logo assets
✅ **Always include 'media' in eager loading**
✅ **Verify storage link exists in production**
