Examinations & Results

The most involved module: it takes a term exam all the way from setup and mark entry through GPA result processing to printed marksheets, tabulation sheets, merit/fail lists and admit cards — following the Bangladesh-board grading rules.

Menu: Examinations & Results Permission: examinations.manage Typical user: Exam Controller / Teacher

The lifecycle at a glance

Setup→ Configure→ Enter marks→ Process results→ Print & publish

1 · Setup

Exams
The exams you run — Weekly, Monthly, Half-Yearly, Final, Grand Final. Each has a merit-processing style (by total mark or grade point, sequential or non-sequential positions).
Grades (grade scale)
The mark-range → letter grade → grade point table, defined per class (e.g. 80–100 = A+ = 5.0).
Short codes
Labels for mark components (e.g. CQ, MCQ, Practical).

2 · Configure the exam

Exam config
Which class configs and subjects an exam applies to.
Mark config
Per subject: its components (short codes), each component's total and the pass mark.
4th subject
Which subject counts as the optional 4th subject for a student (it earns a GPA bonus, not a penalty).
Class-teacher config
Who signs off a class's results.
Signatures & admit instructions
Signature blocks and the instruction text printed on admit cards.

3 · Exam routine

Schedule each subject's exam — date, time and room — so it can be printed and drive admit cards and seat plans.

4 · Mark entry

Teachers open the mark grid for an exam × subject × class config and fill each student's component marks, or tick absent. Rules enforced on save:

  • A mark cannot exceed its component's total.
  • A student is either absent or has marks — never both (absent XOR marks).
  • Marks belong to students actually enrolled in that class config.

All rows save inside one transaction, and mark edits are recorded in the audit log.

5 · Result processing

Processing runs in stages, each idempotent (safe to re-run):

  1. General process
    For each student × subject, component marks are summed and compared against the subject's total pass mark; the class grade scale assigns a letter grade and grade point. Absent ⇒ fail for that subject.
  2. Final process optional
    Combines term results (e.g. to build a Grand Final) using the configured pass rules.
  3. Merit process
    Rolls subject results into a per-student GPA and assigns class & section positions.

How GPA is computed

DecentEdu uses the standard Bangladesh-board method:

base   = sum(grade_point of compulsory subjects)
bonus  = fourth_subject ? max(0, fourth_grade_point − 2.0) : 0
GPA    = round( (base + bonus) / count(compulsory subjects) , 2 )

Pass   = student failed 0 subjects (any fail or absent ⇒ overall FAIL, GPA withheld)

The 4th subject can only help: it adds gradePoint − 2 (never below zero) to the total, but is not counted in the divisor.

Positions (merit rank)

Passing students are ranked to produce a class position (across the whole class) and a section position (within their section). The exam's configuration decides the basis (grade point or total marks) and whether ties advance the next rank (sequential) or skip it (non-sequential).

⚠️

Result processing is a bulk operation. Run General first, then Merit (and Final where used). Re-running is safe — it recomputes, it doesn't duplicate.

6 · Results & printouts

Marksheet

An individual student's result — subject marks, grades, GPA and position.

Tabulation sheet

The whole class in one grid — every student × every subject, with totals and positions.

Merit list

Ranked list of passing students (class-wise or section-wise).

Fail list

Students who failed, with the subjects they failed.

Admit cards, seat plans & attendance sheets

From the exam routine, DecentEdu generates admit cards (with instructions and signatures), allocates a seat plan, and prints an exam-hall attendance sheet. Heavy print jobs are produced as PDF artifacts through the reporting subsystem.
