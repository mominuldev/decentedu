Key Workflows

Most real tasks cross several modules. These end-to-end walkthroughs show how the pieces connect — from an applicant becoming a student, to a term of exams turning into published results, to a fee turning into a ledger entry.

1 · Admission → Enrolled student

Turning an applicant into an active student on the roll.

  1. Open an admission drive
    Create an admission year and define seat quotas (general, and reserved categories). — Admissions
  2. Collect applications
    Applicants are entered with their details; each has a status (pending → selected/rejected/waiting).
  3. Select applicants
    Move applications to selected within the quota.
  4. Convert to student
    One click converts a selected application into a student record and a first-year enrolment into a class config. — Students
  5. Assess fees
    The new enrolment picks up the class's fee structure, ready for collection. — Fees

2 · Daily attendance → Absentee SMS

The everyday teacher/office loop.

Take attendance→ Mark present / absent / late / leave→ Save→ Absentee SMS to guardians
  • Attendance is taken per class config for a date — manually, or ingested from biometric device punches.
  • Holidays and time configs decide what counts as late.
  • Guardians of absent students can be notified using an SMS template (subject to SMS balance). — Messaging

3 · The exam lifecycle

From setting up a term exam to printing marksheets — the system's most involved flow.

  1. Set up the exam
    Create the exam, grade scale (per class), short-codes and configure which subjects & components apply. — Examinations
  2. Configure marks
    Define each subject's components and pass marks (mark configs), plus 4th subjects, class teachers and signatures.
  3. Enter marks
    Teachers fill the mark grid per subject — component marks or absent.
  4. Process results
    General process (per-subject grades) → optional Final process (combine terms) → Merit process (GPA + class/section positions).
  5. Print & publish
    Generate marksheets, tabulation sheets, merit & fail lists, and admit cards / seat plans. — Reports
🎯

GPA uses the Bangladesh-board rule: compulsory subjects average their grade points, and the 4th subject adds a bonus of max(0, gradePoint − 2). Failing any subject makes the result a fail. Full detail on the Exams page.

4 · Fee collection → General ledger

Money in, correctly accounted.

  1. Define the fee structure
    Heads & sub-heads, amounts per class config, due dates and fines, and any per-student waivers. — Fees
  2. Assess dues
    Payable amounts are assigned to students (payable − waiver, + fine if overdue).
  3. Collect a payment
    Open a student's dues, take payment against sub-heads, and print the receipt.
  4. Auto-post to the ledger
    A FeeCollected event raises a receive voucher in Accounting — the GL always matches collections. — Accounting

5 · Year-end promotion (migration)

Rolling a whole cohort into the next session without losing history.

Add new academic year→ Mark it current→ Migrate students (promote)→ New enrolments; old ones preserved

Migration supports promote (advance to the next class), general (re-enrol in the same class) and push-back (reverse a promotion). Because placement is stored per year, last year's results and fees remain intact. — Students · Migration

6 · A student leaves (transfer certificate)

  1. Issue the document
    Create a Transfer Certificate (or Testimonial / Certificate) for the student. — Credentials
  2. Print it
    Render the official printable document with school branding and signatures.
  3. Update status
    The student's status reflects that they've left/transferred; they drop off active rolls but stay in history.
