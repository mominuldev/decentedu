Students

The Students module manages the people at the heart of the school — their identity, guardians and documents, their enrolment in a class each year, and the year-end migration that promotes a whole cohort forward.

Menu: Students Permission: students.manage Typical user: Admin / Front desk

Identity vs. enrolment

DecentEdu keeps a student's identity (name, guardians, photo, contact) separate from their placement (class, section, roll) which is recorded per academic year. This is why the same student can be Class Eight this year and Class Nine next year without ever overwriting history — and why past results and fees always point to the right class.

Student profile

The student form (opened on its own page for create/edit) captures:

Identity
Student ID / admission no, name & name (Bangla), gender, religion, blood group, date of birth, photo.
Guardians & contact
Father's & mother's name and mobiles, student mobile, present & permanent address.
Placement
Academic year, class config, group, category and roll — the current enrolment.
Status
Active, transferred, left or passed-out — the student lifecycle.
🔢

Roll is unique within a class config for a year, and the student ID is unique within the branch — the system prevents duplicates.

The student list

A searchable, filterable roster — filter by academic year, class config, group, category, gender or status. From here you open a profile, edit, or jump to bulk tools. The list can be sent to a clean printable student-list page.

Bulk registration

Admitting a whole class one-by-one is slow, so DecentEdu has a bulk registration grid: pick the academic year and class config, then enter many students row-by-row (name, roll, guardian, mobile…) and save them all at once inside a single transaction. If any row is invalid the whole import is rejected with clear errors, so you never get a half-loaded class. Bulk import is rate-limited to protect the system.

Year-end migration (promotion)

At the end of a session you move students into the new year with Migration rather than editing records. Three modes:

Promote

Advance selected students to the next class in the new academic year.

General

Re-enrol students into the same class (e.g. repeaters, or a fresh year at the same level).

Push Back

Reverse a promotion — undo a migration that was applied by mistake.

Migration creates new enrolments for the target year and updates each student's current enrolment flag, while last year's enrolment (and its results and fees) stays untouched for history and reporting.

⚠️

Always add and mark the new academic year current before migrating. Migration is a bulk, transactional operation — review your selection first.

Documents & credentials

Students can carry supporting documents, and the Credentials module issues their transfer certificates, testimonials, certificates and ID cards.

Reports

Class/section/group/category-wise lists, gender and religion breakdowns, section summaries and student profiles are available as printable reports — see Dashboard & Reports.

At the API level

GET   /api/v1/students                 # list (year/class/group/category/status filters)
POST  /api/v1/students                 # single registration
POST  /api/v1/students/bulk-register   # grid import (throttled)
POST  /api/v1/students/migrate         # promote | general | push_back
GET   /api/v1/students/{id}            # profile
PUT   /api/v1/students/{id}            # update
DELETE /api/v1/students/{id}           # soft delete
