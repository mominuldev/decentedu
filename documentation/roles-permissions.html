Roles & Permissions

DecentEdu controls who can do what with roles and permissions, scoped to a branch. This page lists the built-in roles, the permission catalog, and exactly which permissions each role receives out of the box.

How access control works

  • A permission is a single capability, named module.action — for example fees.manage or audit.view.
  • A role is a bundle of permissions (Admin, Accountant, Teacher, …).
  • A user is assigned a role per branch, so the same person can be an Admin in one campus and, say, an Accountant in another.
  • Permissions can also be granted directly to an individual user, on top of their role, for fine-grained exceptions.

Checks happen in two places: the API (the real security boundary — every module route requires its permission) and the interface (menu items and buttons you can't use are simply hidden). Never trusting the client, the server always re-verifies.

🛡️

Super Admin bypass. The Super Admin role passes all permission checks automatically (a gate “before” hook), but is still bound by the active-branch context when viewing data.

Built-in roles

Super Admin

Platform / organization owner. Full access across modules and branches, user & role management, and cross-branch reporting.

Admin

Full access within a branch — every module and action for their campus. The everyday “school administrator”.

Accountant

Finance only: Fees, Accounting and Reports. No academic, exam or student-management access.

Exam Controller

Examinations and Reports: exam setup, mark entry, result processing and printouts.

Teacher

Classroom-facing: Attendance, Routines and Examinations (mark entry for their classes).

Managing users & roles

Users with users.manage handle this from Administration: create users, assign a role per branch, grant extra permissions, deactivate accounts, and force a password reset. Role → permission edits are also made there.
