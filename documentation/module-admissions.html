Admissions

The Admissions module runs a school's intake: opening an admission drive, defining seat quotas, collecting and screening applications, and finally converting a selected applicant into an enrolled student.

Menu: Admissions Permission: admissions.manage Typical user: Admin / Front desk

The pipeline

Admission year→ Quotas→ Applications→ Selection→ Convert → Student

Admission years (drives)

An admission year is a drive — the intake for a given session (e.g. “2027 Admission”). It groups all the quotas and applications for that round and can be opened or closed.

Seat quotas

Quotas cap how many students you'll admit and reserve seats for categories (general and any special quotas). They give the office a target to select against and prevent over-admission.

Name
The quota's label (e.g. General, Freedom-fighter, Sibling).
Seats
How many applicants may be selected under this quota.
Scope
Tied to the admission year and (optionally) a target class.

Applications

Each applicant is recorded with their personal and guardian details and the class they're applying for. The Applications list supports search, filters and pagination, and a stats summary shows totals by status so the office can see progress at a glance.

Creating or editing an application opens a dedicated form page. An application moves through a status pipeline:

Pending Selected Waiting Rejected

Status changes are made from the application; each change is a deliberate action so the pipeline stays auditable.

Converting to a student

Once an applicant is selected, one action converts the application into:

  • a new student record (identity), and
  • a first enrolment into the chosen class config for the current academic year.

From that moment the student appears on the roll and is ready for attendance, fees and everything else — no re-typing of their details.

✅

Conversion is the bridge between Admissions and Students. It keeps the applicant record for audit while creating the live student.

At the API level

GET/POST/PUT/DELETE  /api/v1/admissions/years           # admission drives
GET/POST/PUT/DELETE  /api/v1/admissions/quotas          # seat quotas
GET   /api/v1/admissions/applications                   # list (search/filter)
GET   /api/v1/admissions/applications/stats             # totals by status
POST  /api/v1/admissions/applications                   # create
POST  /api/v1/admissions/applications/{id}/status       # move in pipeline
POST  /api/v1/admissions/applications/{id}/convert      # → student + enrolment
