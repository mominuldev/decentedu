Dashboard & Reports

The dashboard is your at-a-glance landing screen; the reporting subsystem is the shared engine behind every printable PDF and Excel export across the app.

The counters are cached with a short time-to-live — cheap to recompute and always branch-scoped, so switching branch shows that branch's numbers.

The reporting subsystem

Rather than a report endpoint per module, DecentEdu routes all exports through one entry point backed by a report registry. Each report is a registered generator; the URL slug is validated against the registry. Adding a report means registering a class — not adding routes.

Requesting a report requires the reports.view permission and is rate-limited.

PDF & Excel

Reports render as PDF (print-critical documents like marksheets and admit cards) or Excel (data exports). Large jobs are produced asynchronously as report artifacts so a heavy batch never blocks the browser:

Request report→ Artifact queued→ Poll status→ Download when ready

At the API level

GET   /api/v1/dashboard                          # branch summary counters

# Reporting (requires reports.view, throttled)
GET   /api/v1/reports/{report}/pdf               # e.g. marksheet, tabulation-sheet, admit-card
GET   /api/v1/reports/{report}/excel
GET   /api/v1/reports/artifacts/{id}             # async job status
GET   /api/v1/reports/artifacts/{id}/download    # fetch the finished file
