Academic Setup

Academic Setup is where a school defines its structure — the academic years it runs and the classes, shifts, sections, groups, categories and subjects that every other module builds on. Get this right first: students, attendance, routines, exams and fees all reference it.

Menu: Academic Setup Permission: academic.manage Typical user: Admin

What's in the module

The module is a single page with a tab per resource. Every resource is a simple bilingual reference list (English + Bangla name, a sort order, active/inactive status), except the two config tabs which combine resources into teaching units.

Academic Years

Sessions such as 2025, 2026. One is marked current.

Classes

Six, Seven, … Ten, or college classes.

Shifts

Morning, Day, etc.

Sections

A, B, C within a class.

Groups

Science, Business Studies, Humanities (senior classes).

Categories

General, Residential and similar student categories.

Subjects

Bangla 1st/2nd, English, Mathematics, ICT, Religion…

Class Configs

Class × Shift × Section — the concrete teaching unit.

Group Configs

Which groups are offered in which class.

Academic years (sessions)

An academic year frames the whole system. Records like enrolment, attendance, exams and fees are tied to a year, and exactly one year per branch is the current session. When a new year begins you add it, mark it current, and promote students into it via Student Migration — you don't edit last year's data.

💡

Keep old years active for historical reporting (past results, past fee ledgers). Marking a new year current doesn't delete anything.

Reference lists

Classes, shifts, sections, groups, categories and subjects all share the same simple editor:

Name / Name (Bangla)
Bilingual label shown across the app and on printouts.
Serial
Sort order — controls how items appear in dropdowns and reports (e.g. Class Six before Seven).
Status
Active or inactive. Inactive items are hidden from new selections but preserved on old records.

Class Config — the most important step

A Class Config is the combination of a class, a shift and a section — the actual unit students are placed into and that everything else references. Instead of repeating “Class Nine, Day, Section A” everywhere, the whole system points at one class-config row.

Nine× Day× A= “Nine · Day · A” class config

Create one class config for each real section you teach. From then on:

  • Students enrol into a class config (per year).
  • Attendance and class routines are taken against it.
  • Exam configuration and fee structures are defined per class config.
  • Subject-teacher assignments link a teacher and subject to it.

Group configs

For senior classes that split into streams, group configs record which groups (Science, Business Studies, Humanities) a class offers, so a student's enrolment can carry the right group.

Recommended setup order

  1. Add the academic year and mark it current.
    Everything downstream attaches to it.
  2. Add classes, shifts, sections
    The three ingredients of a class config.
  3. Add groups, categories, subjects
    Groups & categories for enrolment; subjects for routines and exams.
  4. Create class configs
    One per real section. This unlocks Students, Attendance, Routines, Exams and Fees.
  5. Create group configs where classes stream into groups.
⚠️

Reference items are referenced by live records. You can deactivate an item to retire it, but deleting one that's already in use is prevented to protect historical data.

At the API level

Reference resources are served by one generic setup endpoint per module; class configs have dedicated routes.

GET/POST/PUT/DELETE  /api/v1/academic/{resource}      # classes|shifts|sections|groups|categories|subjects|academic-years
GET   /api/v1/academic/class-configs/options          # dropdown data
GET   /api/v1/academic/class-configs                  # list
POST  /api/v1/academic/class-configs                  # create
PUT   /api/v1/academic/class-configs/{id}             # update
DELETE /api/v1/academic/class-configs/{id}            # remove
