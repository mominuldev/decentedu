CMS & Website

A full content-management system for the school's public website — build pages from reusable content blocks, publish posts, notices and events, organize a media library, manage menus, and control SEO and redirects.

Menu: CMS Permission: cms.manage Typical user: Admin / Content editor

What the CMS manages

Pages

Structured pages built from content blocks, arranged in a path hierarchy.

Posts

Blog/news-style articles categorized by taxonomies.

Taxonomies & Terms

Categories and tags that organize posts.

Media library

Images and files, organized in folders, reusable everywhere.

Menus

Drag-and-drop navigation trees for the public site.

Notices & Events

Time-sensitive announcements and calendar events.

SEO

Meta title/description and social fields per content item.

Redirects

Old URL → new URL rules so links never break.

Pages & content blocks

Pages aren't a single blob of HTML — they're assembled from blocks you stack and reorder by drag-and-drop. Each block is a purpose-built section:

HeroPage headerRich text ImageGalleryVideo embed CTAFAQSection Posts listDividerHTML

Editors get a live block editor with a rich-text editor (TipTap) for prose; a page can pull media from the library via a picker. Pages live in a path hierarchy (e.g. /about/history) and use templates (Default, Home, Landing, Full-width) as a rendering hint.

Publishing & safety

Draft → Published
Content has a status and a publish date; only published items appear on the public site.
Soft delete & restore
Deleting a page/post/notice/event is reversible — restore it if removed by mistake.
SEO fields
Every content item carries meta title, description and social preview fields.

Posts, taxonomies & terms

Posts are article-style content (news, articles). Taxonomies (e.g. Category, Tag) and their terms classify posts so the public site can list them by topic. Posts also support blocks, SEO and soft-delete/restore.

Media library

Upload once, reuse anywhere. Media is organized into folders, browsable through a picker inside editors, and supports bulk actions. Uploads are validated for type and size.

Menus

Build the site's navigation as a tree: add items, nest them, and reorder by dragging. Menus are addressed by a key so the public front end can request a specific menu (e.g. main, footer).

Notices & events

Notices are announcements (often with a publish window); Events are calendar entries with dates. Both are first-class, SEO-enabled, restorable content types the public site can list and open by slug.

Redirects

When a page's URL changes, add a redirect so old links (from search engines, bookmarks or printed material) still land in the right place.

Public (rendered-site) API

The CMS exposes a separate set of read-only public endpoints that the rendered website consumes. These return only published content and don't require the cms.manage permission — they're the boundary between the admin CMS and the visitor-facing site.

# Admin (requires cms.manage)
GET/POST/PUT/DELETE  /api/v1/cms/pages | posts | taxonomies | terms | media
                     | media-folders | menus | notices | events | redirects
POST  /api/v1/cms/pages/{id}/restore     # and posts/notices/events

# Public (published content, read-only)
GET  /api/v1/cms/public/pages            GET /api/v1/cms/public/pages/{path}
GET  /api/v1/cms/public/posts            GET /api/v1/cms/public/posts/{slug}
GET  /api/v1/cms/public/notices | events | menus/{key}
GET  /api/v1/cms/public/taxonomies/{taxonomy}/terms
