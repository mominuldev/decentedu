Administration & Audit

The control room: manage users and their roles & permissions, handle sessions and password resets, review the audit log of sensitive actions, and configure branch settings.

Menu: Users & Roles · Audit Log · Settings Permissions: users.manage, audit.view Typical user: Admin / Super Admin

User management

Create and maintain the people who log in. Any authenticated user can read role/permission names (the app needs them to build its own menu), but only users with users.manage can make changes.

  1. Create a user
    Name, email and initial password; attach them to one or more branches.
  2. Assign a role per branch
    Admin, Accountant, Exam Controller, Teacher — or a custom role.
  3. Fine-tune permissions
    Grant extra permissions on top of the role for exceptions.
  4. Lifecycle actions
    Deactivate an account, or force a password reset on next login.

Roles & permissions

View the roles, see the full permission catalog, and update which permissions a role carries. See Roles & Permissions for the complete matrix and how checks are enforced.

Sessions & account security

Change password
Any signed-in user can change their own password.
Active sessions
View your active sessions and revoke one you don't recognize.
Forced reset
Admins can flag an account so the user must set a new password before continuing.
Forgot / reset password
Self-service reset via emailed link from the login screen.

Audit log

Sensitive operations are recorded to an audit log for accountability and dispute resolution — who did what, when, and in which branch. Typical audited events include mark edits, result processing, fee collection and user/permission changes. Reading the log requires audit.view.

🔎

When a parent disputes a mark or a receipt, the audit log is the record of exactly what changed and who changed it.

Branch settings

Per-branch configuration — branch identity (name, code, logo, contact), the current academic year default, and module toggles such as SMS sender ID and grading options — frames how that branch behaves.

Branch switching

Users who belong to several branches switch the active branch from the top bar. Switching re-scopes all data and swaps in that branch's role/permissions and current academic year.
